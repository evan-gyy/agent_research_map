# RAG 项目如何进行分批评估？

## 原题原文

> 分批评估怎么进行的？

## 答案

### 面试直答

RAG 分批评估要按链路和风险分层，而不是随机把数据切成几份。常用做法是先用小规模冒烟集快速迭代，再跑固定核心回归集、长尾专项集和完整端到端集；每批都保持版本、指标和停止条件一致。

### 一、四批评估

| 批次 | 数据 | 目的 |
|---|---|---|
| Smoke | 20～50 条代表样本 | 快速发现解析、索引和 Prompt 基本错误 |
| Core | 高频业务与关键知识 | 版本回归和主指标比较 |
| Slice | 表格、长文档、时效、无答案、对抗问题 | 定位特定失败模式 |
| Full/Online | 全量冻结集与灰度流量 | 发布决策和真实分布验证 |

每批都要保存标准证据，而不只有参考答案，才能分别计算 Recall@K、MRR/nDCG、忠实度和引用准确率。

> **核心小结：** 小批次提高迭代速度，固定回归集保证可比，专项集暴露长尾，全量和线上决定能否发布。

### 二、逐层定位

先评数据解析和 Chunk，再评召回与排序，最后评生成和端到端。若正确证据没有进入 Top-K，调 Prompt 没有意义；若检索命中但答案错误，再查 Context 拼接、指令和模型。

> **核心小结：** 分批还要分层，避免用最终答案分数掩盖检索或数据问题。

### 三、工程实践

- 数据集、索引、Embedding、Reranker、Prompt 和模型都记录版本。
- 一次只改变一个主要变量，保留可解释的对照实验。
- 使用置信区间和失败桶，不因小样本的随机波动提前下结论。
- 线上失败脱敏后进入专项集，防止同类问题回归。
- 发布门槛同时包含质量、P95 延迟、成本和安全。

> **核心小结：** 分批评估的价值是更快、更可定位，而不是把同一总分拆成多个表。

### 常见追问

- **每批多少条？** 由失败率和置信要求决定；冒烟集可以小，发布集必须覆盖各业务桶。
- **可以每批调不同 Prompt 吗？** 可以探索，但最终比较必须回到同一冻结版本。

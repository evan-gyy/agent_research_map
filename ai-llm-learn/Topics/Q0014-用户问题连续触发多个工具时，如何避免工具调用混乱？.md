# 用户问题连续触发多个工具时，如何避免工具调用混乱？

## 原题原文

> 高频追问：用户问题连续触发多个工具时，怎么避免工具调用混乱？

## 答案

### 面试直答

连续多工具调用要避免混乱，关键是使用结构化计划和状态：每个 Tool Call 有唯一 ID、依赖、输入来源和状态；Harness 校验 Schema、权限和前置条件，结果按 ID 配对，再决定可并行还是串行。

### 一、调度

无依赖的查询工具可并行；后一步参数依赖前一步结果时必须串行。写操作使用幂等键和资源锁。模型不能仅凭自然语言猜“上个工具应该成功了”。

> **核心小结：** 多工具正确性来自依赖图和结果配对，不是调用顺序碰巧正确。

### 二、保护

- Tool Result 包含 success/error/retryable 和标准字段。
- 参数来源可追踪，跨工具传值再次校验。
- 部分失败只重试失败节点。
- 总步骤、并发和 Deadline 有预算。
- 记录工具版本和副作用状态。

> **核心小结：** 工具链应像小型工作流执行器，而不是自由文本接龙。

# 为什么选择 RAG 而不是微调？两者应该如何取舍？

## 原题原文

> 微调和 RAG，为什么使用 RAG 不用微调？

## 答案

### 面试直答

RAG 和微调解决的问题不同：**RAG 主要注入可更新、可引用的外部知识；微调主要改变模型的行为、风格、格式和任务能力。** 知识频繁变化、需要来源时优先 RAG；需要稳定输出习惯或领域技能时考虑微调，生产中也常组合使用。

### 一、选型对比

| 维度 | RAG | 微调 |
|---|---|---|
| 更新知识 | 改索引即可 | 需重新训练 |
| 可追溯 | 可返回引用 | 较弱 |
| 私有数据隔离 | 检索时按权限过滤 | 权重中难精确删除 |
| 改变行为 | 有限 | 更适合 |
| 推理开销 | 有检索和长 Context | 模型调用更直接 |

> **核心小结：** “记住新事实”优先 RAG，“学会稳定做事”优先微调。

### 二、判断流程

先做 Prompt + RAG 基线。如果错误来自检索不到知识，优化数据和召回；如果证据正确但模型持续不会按领域规则推理或输出，再评估 SFT/偏好优化。微调后仍可使用 RAG 提供最新事实。

> **核心小结：** 先定位瓶颈再选技术，不能因为微调听起来更高级就使用微调。

### 三、风险

RAG 有检索延迟、漏召回和上下文噪声；微调有数据成本、遗忘、版本维护和知识难删除。两者都要用独立评测集验证端到端收益。

> **核心小结：** 选型应同时考虑效果、更新频率、引用要求、延迟和运维成本。

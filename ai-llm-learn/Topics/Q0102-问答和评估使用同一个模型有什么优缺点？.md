# 问答和评估使用同一个模型有什么优缺点？

## 原题原文

> 问答和评估使用的是同一个模型吗？是，有什么优劣？

## 答案

### 面试直答

问答和评估使用同一个模型的优点是部署简单、成本可控、风格一致；缺点是存在**自我偏好和相关性错误**，模型可能认可与自身生成习惯相似的答案，无法独立发现系统性缺陷。低风险迭代可以同模，高风险发布不能只靠同模自评。

### 一、优缺点

| 维度 | 同一个模型 |
|---|---|
| 优点 | 接入简单、延迟和成本较低、无需维护第二套模型 |
| 缺点 | 自我偏好、共同盲区、提示注入风险、分数独立性弱 |
| 适用 | 开发期快速回归、格式检查、低风险主观任务 |
| 不适用 | 安全、合规、财务等高风险发布裁决 |

模型既当运动员又当裁判时，即使温度不同，也没有真正消除相关误差。

> **核心小结：** 同模评估适合快速反馈，不适合作为唯一的最终质量证明。

### 二、降低偏差

- Judge 不读取生成模型身份和隐藏推理，只看问题、证据、答案与 Rubric。
- 使用确定性规则或执行结果优先判定可验证部分。
- 用人工金标校准 Judge，监控与人工的一致率和各错误桶偏差。
- 对高风险样本使用异构模型、多 Judge 或人工复核。
- 防止被评答案中的文本注入 Judge Prompt，使用明确数据边界。

> **核心小结：** 独立性来自数据、模型和判定机制的解耦，而不是简单换一个 Prompt。

### 三、选型建议

开发阶段可用同模 Judge 提高迭代速度；发布阶段使用“规则/执行验证 + 独立 Judge + 人工抽检”；线上持续监控误判。成本有限时，把异构评估集中到分歧样本和高风险桶。

> **核心小结：** 评估架构应按风险分层，把昂贵的独立验证用在最值得的位置。

### 常见追问

- **换温度算独立评估吗？** 不算，只增加采样差异，模型偏好仍高度相关。
- **Judge 一定要更强吗？** 不一定，但要在目标 Rubric 上经过人工校准。

# 文档如何分块？固定大小如何设置？语义不连贯时怎么办？

## 原题原文

> 文档分块怎么分的？固定大小设置多少？如果分的时候语义不连贯怎么办？

## 答案

### 面试直答

分块应优先遵循文档结构和语义边界，固定大小只作为兜底。Chunk 要在“足够小便于准确召回”和“足够大能独立回答”之间折中；大小通过目标模型 Token、文档类型和评测集确定。

### 一、策略

先按标题、段落、列表、代码块和表格切分；过长节点再按句子和 Token 递归切。普通说明文可从数百 Token 做实验起点，但不存在通用最佳值。Overlap 只用于边界信息，不应大量复制。

> **核心小结：** 结构优先、Token 限制兜底，固定数字只是实验起点。

### 二、语义不连贯的处理

- 保留标题路径和父文档元数据。
- 使用父子索引或召回后邻域扩展。
- 表格、代码和定义不可在内部随意切断。
- 用模型或规则检测不完整句，但避免每块都昂贵调用。

> **核心小结：** 语义连贯既靠切分，也靠父子关系、元数据和检索后扩展。

### 三、评估

按不同 Chunk/Overlap 网格实验，比较 Recall@K、答案正确性、重复率、Context Token 和延迟。

> **核心小结：** 最终参数由端到端评测决定，而不是沿用网上经验值。

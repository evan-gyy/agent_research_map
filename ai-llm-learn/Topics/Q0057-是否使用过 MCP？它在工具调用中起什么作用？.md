# 是否使用过 MCP？它在工具调用中起什么作用？

## 原题原文

> 工具的话你会用MCP之类的吗？

## 答案

### 面试直答

MCP 的作用是把文件、数据库、文档平台和业务 API 以统一协议暴露给 Agent，使 Host 可以发现工具、读取 Schema、调用并接收结构化结果。它减少每个 Agent 与每个系统单独写适配器的成本，但不是 Agent 框架或权限系统。

### 一、项目回答方式

如果结合实际集成经验，可以说明：Host 通过 MCP Server 获取工具清单，模型只看到允许的工具；调用前校验 Schema 和权限，执行后检查真实返回，再判断是否达成业务效果。仅“连接成功”或“资源列表为空但无报错”不能证明集成可用。

> **核心小结：** MCP 集成的完成标准是工具对真实资源产生可验证效果，而不只是握手成功。

### 二、价值与边界

价值包括统一发现/调用、服务复用和动态扩展；代价包括 Tool Schema Token、连接稳定性、权限传递和第三方 Server 信任。大量工具需要 Tool Search 或路由按需加载。

> **核心小结：** MCP 提供协议层复用，Harness 仍要负责选择、审批、观察和评估工具。

## 证据规则

每条关键结论标记为以下一种：

- **官方文档确认**：产品官方明确描述的行为。
- **公开源码确认**：能在公开仓库定位到实现或测试；记录仓库和提交版本。
- **概念映射**：为了教学，把公开行为映射到 ReAct、Plan、Workflow 等概念；不能说成产品官方命名。
- **工程建议**：根据约束给出的设计建议，不代表任何产品现状。
- **待核验**：暂时没有足够证据，不进入确定性结论。

第三方博客可以提供线索，但关键机制应尽量回到官方文档、官方仓库或可复现行为。

## 第一阶段研究顺序

1. 规划与执行：Plan、动态工具循环、固定 Workflow 如何组合。
2. Context 管理：压缩、稳定规则重注入、Tool Schema、子 Agent 隔离。
3. Tool / MCP：工具发现、延迟加载、参数校验、权限控制。
4. 子 Agent：上下文继承、并发模型、结果汇总和写冲突。
5. 权限与安全：沙箱、审批、Hooks、规则与高风险动作。
6. 长任务与恢复：Checkpoint、会话持久化、暂停和续接。
7. 可观测与评估：步骤、工具、成本、延迟和正确性如何分层评估。
